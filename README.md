定时统一上报：

- INC/VIB 共用一个上报刻度和频率，所有水位设备共用另一个上报刻度和频率。采集完成后只落库，到点从数据库选取各启用测点的最新有效数据，按 MQTT 网关组包发送一次。
- 每组使用调度器计划的时间 `T`，写入所有条目的 `value[][0]`；任务晚执行几秒不改变 `T`。外层 Java 字段 `sampleTime`（实际 JSON 名 `sample_time`）为本次发送尝试的时间，同一报文各条目一致。平台应按 `value[][0]` 存储和绘图。
- 所有时间窗口均按数据库 `data_time` 的真实采集时间计算，包含两个端点。INC/VIB 在 `[T - 1h, T]` 内有数据时直接使用真实值；没有1小时内数据、但在 `[T - 4h, T - 1h)` 内有数据且具备足够正常历史时使用历史波动模型模拟；4小时内也没有数据则跳过。采集时间晚于 `T` 不参与取数，某个测点缺失不阻塞其他测点。水位仍仅使用75分钟有效期内的真实值，不启用模拟。
- 同一条真实源记录可以用于多个上报刻度，但超过真实有效期的条目必须标记为模拟。发送仅修改报文副本的时间，不改写数据库快照。应用启动后从下一个刻度开始，不补发停机期间的历史刻度。
- 未连接、发送失败或取数失败均仅记录日志，不保存待发送任务、不重试。下一刻度重新查询数据库；MQTT 使用原有 QoS 0，发送完成不代表平台已入库。
- `device-report` 可配置两组的 cron、真实有效期和时区；某组 cron 设为 `"-"` 可关闭该组上报，采集仍继续。INC/VIB、水位仍均在北京时间每小时整点上报。INC/VIB 的 `max-age` 默认1小时，`simulation.enabled` 默认开启，`simulation.max-source-age` 默认4小时；关闭模拟后超过真实有效期即跳过。水位的 `max-age` 保持75分钟。
- INC/VIB 的 HTTP 拉取仍为每2分钟；水位设备 `frequency` 仍控制 Modbus 查询周期，不再控制 MQTT 上报频率。接口解析及采集入库放到 Vert.x Worker 线程执行，统一上报在调度线程执行。

```yaml
device-report:
  zone: Asia/Shanghai
  incline-vib:
    cron: "0 0 * * * *"
    max-age: 1h
    simulation:
      enabled: true
      max-source-age: 4h
      history-window: 48h
      history-size: 24
      min-history-size: 6
      max-history-gap: 90m
      volatility-scale: 1.0
      seed: 20261101
  water-level:
    cron: "0 0 * * * *"
    max-age: 75m
```

INC/VIB缺测模拟：

- 算法为 `HISTORICAL_AR1`：对同一测点、同一SN最近48小时内最多24条真实记录学习，每条原始采集时间只计一次。学习截止于最近真实源记录，不能使用该源时间之后的记录。至少需要6条连续、明确正常且无报警的记录；遇到无效数据、报警/故障/未知状态、零点模式或倾角基准切换、超过90分钟的采集断档时截断学习窗口。已过滤或仍待确认的VIB点不在留存表中。
- 每个数值字段学习均值 `μ` 和相邻记录相关系数 `φ`，按 `x_next = μ + φ × (x_previous - μ) + ε` 生成。基础AR公式参考 [NIST统计手册](https://www.itl.nist.gov/div898/handbook/pmc/section4/pmc444.htm)；本项目增加系数限制、历史残差向量重采样、时间间隔处理及范围约束。`φ` 限制在 `[-0.95, 0.95]`，`ε` 从训练记录的中心化残差中抽取，并乘以 `volatility-scale`。INC的X/Y角度和温度使用同一个历史残差向量，保留字段之间的残差关联，不分别添加独立固定幅度噪声。
- 以历史采集间隔中位数推进模型，从最后真实值生成至本次整点，部分间隔按比例推进。数值限制在正常学习记录的最小值与最大值之间，每个完整采样步的变化量限制为历史相邻绝对变化量的95%分位数。INC保持角度6位、温度3位，VIB保持4位小数。不重新应用当前基准，不把模拟结果送入真实尖峰过滤窗口。
- 历史不足、所有字段完全平坦或无法形成有效模型时跳过，不回退到保持原值，也不设置与真实历史无关的噪声下限。某个字段历史平坦时保持该字段；学习有波动的其他字段。生成值经原有精度舍入后偶尔相同是允许的，不强行制造每条都不同的数据。
- `history-window`、`history-size`、`min-history-size`、`max-history-gap` 可调整学习范围；学习条数须满足 `6 <= min-history-size <= history-size <= 1000`。`volatility-scale` 在 `(0,1]` 内调节残差波动强度，默认1；`seed` 控制随机路径，相同真实历史、配置和上报时刻在重启或重复计算后得到相同结果。每次最多推进256个采样步，超过时跳过。
- 实测与模拟条目统一使用原有协议：外层只有 `data_tag`、`mqtt_data`，每个条目只有 `sample_time`、`device_id`、`device_type`、`value`。不附加 `simulated`、`source_time`、`simulation_method`，这些字段也不入库。`value` 的列顺序、数值类型及精度不变，首列仍为平台对齐时间；模拟算法、真实源时间及学习条数保留在本地运行日志中供排查。
- 模拟结果只存在于当次报文中，不插入采集表、不刷新源记录时间、不更新状态页的真实采集状态。下一轮仍查真实源记录，因此不会通过模拟继续给模拟续期。收到新真实记录后自动恢复真实上报。这个统计模型生成的是估算波动，不能证明设备当前状态或缺测期间没有振动事件。
- 例：最近真实记录在10:00，11:00恰好1小时仍使用真实值；12:00、13:00、14:00具备有效学习历史时生成带波动的模拟值，15:00超过4小时跳过。1小时、4小时两个参数均可配置；启用时模拟窗口必须大于真实有效期。
- 日志逐条记录模拟测点、真实源时间、平台时间、算法及学习条数，并分别统计本轮实测/模拟候选条目数；候选数不表示平台已成功接收。模拟也遵守到点发送一次、不重试、不补发的规则。

采集数据留存（复用原有两张表，不增加批次表或队列表）：

- 启动时自动创建 `incline_forward_data` 表，沿用旧表名。INC、VIB 通道分别保存处理快照；VIB 待确认或被过滤的点不入表。有效期内可回退使用上一条已放行数据。
- `device_code` 为测点，`remote_device_id` 为传感器 SN，`data_time` 为原始采集时间；新记录的 `sample_time` 也使用原始采集时间戳，旧记录可能为当时的构建时间，不参与有效期判断；`create_time` 为入库时间。
- `payload` 保存原始采集时间及基准扣减、换算、舍入后的值，`raw_data` 保存接口单条原始记录 JSON。原始采集时间与定时上报时间分开处理。
- 采集入库失败不推进查询进度，保留原有下一轮继续采集的机制；部分通道成功后其他通道失败，可能产生重复快照。查询相同采集时间时取 ID 最大的一条，每个测点每个刻度只选一条数据。
- 每天北京时间03:00按 `create_time` 清理入库超过45天的 INC/VIB 快照，恰好位于阈值的记录保留。
- 水位复用 `water_level_data`，启动时自动补充可空的 `payload` 字段，保存采集时算好的差值及原始水位；设备协议没有采集时间，因此使用服务器接收时间。没有 `payload` 的旧记录保留但不上报，不用当前基准倒推原始值。早期 `record_time` 字段会自动迁移为 `data_time`，保留原记录。
- 水位维持原有48小时清理规则。现有设备表中的启用状态、类型及网关映射决定哪些测点参与上报；INC/VIB 还核对当前配置的 SN。

```sql
SELECT device_code, remote_device_id, device_type, data_time, payload, raw_data
FROM incline_forward_data
ORDER BY id DESC
LIMIT 100;
```

倾角固定基准：

- 在 `/device-status.html` 的 INC 设备行点击“设置基准”，可手动填写 X/Y 基准，或点击“使用最新原始值”后保存。界面显示所选原始数据的时间和状态。未设零点时由采集自动初始化；已有零点时按其保持不变处理。
- 基准按 INC 设备编号独立保存，单位为度。设置后，后续转发及状态页 `angleX`、`angleY` 先将原始角度扣零，再按前后两条扣零原始值的增量累加；未设置或清除基准后，由下一批有效新数据自动初始化。温度、VIB、水位不参与此扣减。
- 状态页的 `rawAngleX`、`rawAngleY` 保留原始值；采集快照的 `raw_data` 也保留原始记录，`payload` 留存采集时的扣减结果。原始记录不会被改写，基准不会随每次采集自动滚动。
- 基准保存在现有设备表 `s_device_info_ext` 的 `incline_baseline` 字段中，SQLite 使用 `TEXT` 存储 JSON。应用启动时自动补充该字段，不修改原有水位 `baseline` 字段。扣零功能读取设备基准；本次增量放大按零点保持不变处理，不重算历史记录。
- 每台设备的一行保存该设备的基准，字段为 `NULL` 时不扣减。JSON 包含 `angleX`、`angleY` 和 `updatedAt`（UTC 设置时间），例如：

```json
{
  "angleX": 1.5,
  "angleY": -2.56,
  "updatedAt": "2026-11-01T00:00:00Z"
}
```

接口（仅已配置的 INC 设备允许设置或清除）：

- `GET /api/incline-baselines`：查询全部固定基准。
- `PUT /api/incline-baselines/{deviceCode}`，JSON 请求体 `{"angleX":1.5,"angleY":-2.56}`：创建或替换该设备的基准，两个轴均必填，零值有效。
- `DELETE /api/incline-baselines/{deviceCode}`：清除该设备零点基准；下次收到有效新数据时会自动重新初始化。

倾角统一2倍增量入库：

- 过滤重复采集时间后，若INC测点尚无零点，取本批时间最新且X/Y、温度均有效的记录，将其原始X/Y写入现有零点基准，并将该条X/Y以`0.000000`入库。此时本批较早的新INC记录不入库，已有历史不改写；VIB仍按原顺序处理。只有重复或无效数据时不初始化。
- 零点与0值快照在同一数据库事务中保存，失败时一起回滚并保留该条重试机会。数值为0的已有基准同样视为已设置，不会覆盖。重启后读取已保存零点和原始/处理快照继续累加。
- 已有零点但没有有效前值时，`入库角度 = 当前原始角度 - 零点基准`。后续按 `本次入库 = 上次入库 + (当前扣零原始值 - 上次扣零原始值) * factor`；零点未变时，差值就是前后两条原始角度之差。例如自动以首个新值`1.5000`为零点后，后续原始`1.5001 → 1.5001`入库为`0.0002 → 0.0002`，稳定数据不会来回振荡。
- 从现有 `incline_forward_data` 查询同测点、不晚于当前采集时间的最新INC记录；`raw_data` 提供上次原始角度，`payload` 提供上次入库角度。重启后直接恢复续算，不依赖内存保存的上次数值。不新增数据库列、报文或状态接口字段。
- 按零点保持不变处理，不检测零点变更。已有零点但没有有效历史或换SN时，第一条扣零起算；不更改设备更新时间或快照入库时间。
- 每次从数据库读取前值，不维护额外内存状态；入库失败时保留原有采集重试机制。相同采集时间重试时，数据库中的原始值与当前值相同，增量为0，不会重复放大。历史不回写、不重算。
- 结果仍写入原有 `payload` 的X/Y位置及状态缓存 `angleX/Y`，角度最终保留6位小数；`raw_data`、`rawAngleX/Y` 保留原始值。温度、振动、水位和设备原始报警状态保持原有处理。定时上报直接使用入库值，不再次放大。
- 统一倍率直接配置在主配置文件 `application.yml` 的 `incline.fluctuation` 下，默认 `enabled=true`、`factor=2`，不再配置各设备固定中心。所有INC设备使用同一倍率，包括新增设备。关闭放大或设为1时直接扣零入库，配置修改需重启。
- 历史模拟继续学习已处理的 `payload`，用 `factor * raw - payload` 的相邻差异识别累加起点切换（允许6位小数舍入误差），输出不再放大。模拟与实测均使用原MQTT字段，不附加模拟标记。
- 统一增量放大会同时放大真实变化与噪声，不能作为灵敏度标定或设备健康证明。原数据统计和按窗口首条起算的离线算例见 [评估报告](document/incline-fluctuation-assessment/assessment.md)。复算命令：`python3 scripts/analyze_incline_fluctuation.py <ZIP路径> --output <报告目录> --config <配置片段输出路径>`；生成配置片段只包含开关和统一倍率，按需合并到主配置，不要用片段覆盖整个 `application.yml`。

振动孤立尖峰过滤：

- `vibration.filter` 默认作用于 `ZYXH-VIB-P01-002-02`、`CBXH-VIB-P01-001-03`，保留现有 Z 轴通道和 mG → m/s² 换算。
- 只过滤相邻三条采集记录中的单条孤立尖峰。突增判据满足以下任一分支：绝对幅值比邻点至少增大 `spike-min-delta`（默认 2 m/s²）；或绝对幅值达到历史基线的 `spike-ratio`（默认 10）倍，同时比邻点至少增大 `relative-min-delta`（默认 0.05 m/s²）。确认时，中间点对前后邻点均须满足突增判据；后一条必须恢复，且前后点的有符号差值不超过 `return-tolerance`（本项目 YAML 建议配置 0.05 m/s²，未配置时类默认值为 0.5 m/s²）。恢复容差过小会使孤立尖峰因未恢复而被保留；它不是振动幅值上限。2 是幅值增量，不是绝对值上限或 ±2g 量程。
- 历史基线取最近 `baseline-window-size`（默认 24）条正常记录的绝对幅值中位数；不足时使用已有记录，首条直接放行。倍数计算使用 `noise-floor`（默认 0.001 m/s²）作为分母下限，防止基线接近零时放大倍数。待确认点、连续高值、报警/故障/状态未知记录不进入基线。
- 正常点立即入库，等待定时任务统一上报；疑似尖峰等下一条确认。若第二条相对突增前邻点和冻结的历史基线仍满足突增判据，两条立即原值放行；本轮后续高值持续放行，直到恢复基线，期间不再暂存或过滤单点。恢复后才重新识别下一轮孤立尖峰。未恢复、任一点报警/故障/状态未知时保留。空值和非有限数直接跳过，并打断相邻关系；无效数据、状态异常、采集间隔过长或待确认超时后重新建立历史窗口。
- 相邻采集间隔上限及待确认超时为 `max-gap-seconds`（默认 5400 秒，适配当前约每小时一条的上报周期）。缺少邻点、间隔过长、等待超时时无法确认孤立性，按原值放行；超时任务每分钟检查一次。
- 延后放行保留原始采集时间，定时上报仍按此时间判断有效期，确认丢弃的点仅记录到告警日志。入库失败回滚窗口状态，保留重试机会。窗口保存在内存中，进程重启后重新建立。
- 接口文档把 `accMaxX/Y/Z` 定义为各轴在采样周期内的最大变化量，把 `accX/Y/Z` 定义为重力加速度分量；后者不替代振动峰值。文档未明确这些字段的单位，当前沿用已有 mG 换算，仍需设备方确认。
- 该规则只做周期统计值的去尖峰，不能证明峰值一定是假数据；真实短时冲击也可能只占一条记录。报警记录保留供核查，振荡分析仍需要更高频率的原始波形。
