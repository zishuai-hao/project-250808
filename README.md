定时统一上报与补发：

- INC/VIB、水位均在北京时间每小时整点发送，只使用真实采集快照，已移除缺测模拟。时间窗口为 `(T - 1h, T]`，例如12:01～13:00的数据归属13:00；12:00:00归属12:00，12:00:01归属13:00。同一条源记录不会滚动到下一小时继续发送。
- 每个测点、每个小时只选最新一条。更早的采集记录保留供曲线查看，但不逐条发送；查询先选最新记录，再检查发送状态，避免已成功后回退发送该小时的旧值。采集时间相同时兼容旧库重复记录，取ID最大者。
- 报文 `value[][0]` 使用数据所属整点；补发也保留这个原整点。外层 `sample_time` 使用实际发送时间。报文字段、数值精度及已有的基准扣减、倾角增量处理保持原有规则。模拟开关及 `max-age` 配置已移除，不再允许使用更老数据填充当前小时。
- 默认每5分钟扫描最近24小时、已经结束的各小时，补发各测点的最新未成功记录。当前尚未结束的小时不提前发送；停机重启后也从数据库恢复待发送状态。超过24小时的记录保留供查询，不再自动补发。
- 某小时发过一条后，若又补录一条采集时间更晚的数据，会将该小时的新最新值补发；更早或相同采集时间的迟到记录不再发送。即使相同时间的数据重复入库产生新ID，也不会绕过成功状态。接收平台应按“测点 + 所属整点”更新同一个小时的数据。
- 每条采集记录新增 `report_status`：`PENDING`（尚未发送，包含未被选中的旧值）、`SENDING`（发送中）、`SENT`（MQTT提交成功）、`FAILED`（失败，等待扫描重试）。同时保存 `report_time`（所属整点）、`report_attempts`、`report_attempted_at`、`report_sent_at`（Unix毫秒）及 `report_error`。`report_token` 仅用于防止过期尝试覆盖新结果。
- MQTT异步回调成功后才标记 `SENT`。断线、禁用网关、同步异常、异步失败、30秒无结果或快照不可用均保留失败状态；一个网关失败不阻塞其他网关。抢占时在同一条SQL内重新校验候选仍是该小时最新值、未发送过相同或更新值，并阻止同测点同小时的不同记录并行发送，避免过期候选在新值之后发出。进程崩溃遗留的 `SENDING` 在两分钟后允许重领。
- 沿用 MQTT QoS 0，`SENT` 表示客户端提交成功，不是平台业务入库回执。发送成功但本地状态落库前崩溃、或超时后实际送达等情况仍可能重复提交，接收端需按上述小时键幂等处理。
- 两张采集表启动时自动补充状态列。旧版本未留存发送结果，升级后旧记录初始为 `PENDING`，最近24小时符合条件的数据可能重新发送；不会伪造旧记录已成功。历史快照的数值和采集时间不改写。

```yaml
device-report:
  zone: Asia/Shanghai
  retry-cron: "0 */5 * * * *"
  incline-vib:
    cron: "0 0 * * * *"
  water-level:
```

`retry-cron: "-"` 关闭补发；某组 `cron: "-"` 同时关闭该组的正常发送和补发，采集继续。正常发送的cron只接受每小时整点或关闭，避免配置出重叠窗口。

采集回查与留存：

- INC/VIB保持每2分钟通过历史接口拉取，但每次回查最近24小时（启动时也回查），按采集时间升序读取全部分页，不再只查询最新游标之后的数据。分页失败不处理不完整窗口；401最多刷新并重试一次，保留原查询时间范围。
- 按 `device_code + remote_device_id + device_type + data_time` 原子去重入库。重复拉取不会覆盖已处理的值、重置发送状态或产生新快照；部分通道入库失败时可以单独补齐。
- 迟到INC按其采集时间之前的数据库快照续算，已有历史不回写、不重算，也不重新设零。未设置零点时仍先用最新有效新记录初始化零值，再在已有基准下补齐窗口内缺口。补录旧数据不会倒退状态页最新采集时间或刷新在线时间。
- 迟到VIB在独立、有序的24小时历史窗口中使用原尖峰规则判断，不扰动实时过滤窗口；确认过滤的采集时间保存到 `incline_vibration_filtered`，重启或滚动窗口移走前邻点后也不会将其复活为缺口。待确认点不足邻点时继续等待；超过原90分钟阈值后按原值放行。
- `incline_forward_data` 沿用现有表。`data_time` 为真实采集时间，`payload` 保存采集时算好的值及采集时间，`raw_data` 保存接口原始记录；新记录的 `sample_time` 为原始采集时间戳。每天北京时间03:00清理入库超过45天的快照，并清理45天前的过滤标记。
- 水位复用 `water_level_data`，保留48小时清理规则，使用服务器接收时间和采集时固定的差值/原始水位。无 `payload` 的旧水位数据不参与发送；旧 `record_time` 字段仍自动迁移为 `data_time`。水位无远端历史接口，补发仅使用已入库记录。
- 当前启用状态、设备类型、MQTT网关以及INC/VIB当前SN决定参与上报的测点。

```sql
SELECT id, device_code, data_time, report_time, report_status,
       report_attempts, report_sent_at, report_error
FROM incline_forward_data
ORDER BY data_time DESC, id DESC
LIMIT 100;
```

设备观测曲线：

- 在 `/device-status.html` 点击设备编号即可弹出历史观测曲线。时间范围横向排列，默认最近24小时，支持1小时、6小时、24小时、48小时、7天及自定义起止时间（北京时间），并可手动刷新。
- 使用本地ECharts 6.1.0叠加同一设备的多条曲线：INC的X/Y倾角共用左轴、温度使用右轴；VIB显示Z轴振动；WLV叠加水位差值和原始水位。点击图例开关曲线，拖动底部滑块或滚轮缩放；鼠标移动、触摸或聚焦图表后使用左右方向键可查看采集时间及精确数值，时间统一显示为北京时间。
- 曲线读取真实采集快照，悬浮或选择数据点可查看发送状态、所属整点及尝试次数。历史接口每个 `point.delivery` 返回 `status`、`reportTime`、`attempts`、`sentAt` 和 `error`。倾角使用入库时已处理的数值，不按当前基准重新计算；水位旧记录只有差值时，原始水位显示为缺失。无数据、缺失值和加载失败均有提示。
- `GET /api/device-history/{deviceCode}?hours=24` 查询最近指定小时的数据（1至1080小时），按原始采集时间升序返回。同一时间取最后入库记录，INC/VIB仅查询当前配置SN；最多返回最新2000条，超出时界面提示缩小范围。实际可查询范围受现有留存策略限制：INC/VIB为45天，水位为48小时。图表无需外部CDN。
- 自定义查询使用 `GET /api/device-history/{deviceCode}?start=2026-11-04T00:00:00Z&end=2026-11-04T08:00:00Z`，起止时间均为带时区的ISO时间，包含两个端点；不能与 `hours` 同时指定，起始须早于结束且跨度最多45天。页面会将填写的北京时间转换成UTC请求。

倾角固定基准：

- 在 `/device-status.html` 的 INC 设备行点击“设置基准”，可手动填写 X/Y 基准，或点击“使用最新原始值”后保存。界面显示所选原始数据的时间和状态。未设零点时由采集自动初始化；已有零点时按其保持不变处理。
- 基准按 INC 设备编号独立保存，单位为度。设置后，后续转发及状态页 `angleX`、`angleY` 先将原始角度扣零，再按前后两条扣零原始值的增量累加；未设置或清除基准后，由下一批有效新数据自动初始化。温度、VIB、水位不参与此扣减。
- 状态页的 `rawAngleX`、`rawAngleY` 保留原始值；采集快照的 `raw_data` 也保留原始记录，`payload` 留存采集时的扣减结果。原始记录不会被改写，基准不会随每次采集自动滚动。
- 基准保存在现有设备表 `s_device_info_ext` 的 `incline_baseline` 字段中，SQLite 使用 `TEXT` 存储 JSON。应用启动时自动补充该字段，不修改原有水位 `baseline` 字段。扣零功能读取设备基准；本次增量放大按零点保持不变处理，不重算历史记录。
- 每台设备的一行保存该设备的基准，字段为 `NULL` 时不扣减。JSON 包含 `angleX`、`angleY` 和 `updatedAt`（UTC 设置时间），例如：

```json
{
  "angleX": 1.5,
  "angleY": -2.56,
  "updatedAt": "2026-11-01T00:00:00Z"
}
```

接口（仅已配置的 INC 设备允许设置或清除）：

- `GET /api/incline-baselines`：查询全部固定基准。
- `PUT /api/incline-baselines/{deviceCode}`，JSON 请求体 `{"angleX":1.5,"angleY":-2.56}`：创建或替换该设备的基准，两个轴均必填，零值有效。
- `DELETE /api/incline-baselines/{deviceCode}`：清除该设备零点基准；下次收到有效新数据时会自动重新初始化。

倾角统一2倍增量入库：

- 过滤重复采集时间后，若INC测点尚无零点，取本批时间最新且X/Y、温度均有效的记录，将其原始X/Y写入现有零点基准，并将该条X/Y以`0.000000`入库。先初始化最新记录，再通过24小时回查补齐较早缺口；已有历史不改写，VIB仍按原顺序处理。只有重复或无效数据时不初始化。
- 零点与0值快照在同一数据库事务中保存，失败时一起回滚并保留该条重试机会。数值为0的已有基准同样视为已设置，不会覆盖。重启后读取已保存零点和原始/处理快照继续累加。
- 已有零点但没有有效前值时，`入库角度 = 当前原始角度 - 零点基准`。后续按 `本次入库 = 上次入库 + (当前扣零原始值 - 上次扣零原始值) * factor`；零点未变时，差值就是前后两条原始角度之差。例如自动以首个新值`1.5000`为零点后，后续原始`1.5001 → 1.5001`入库为`0.0002 → 0.0002`，稳定数据不会来回振荡。
- 从现有 `incline_forward_data` 查询同测点、不晚于当前采集时间的最新INC记录；`raw_data` 提供上次原始角度，`payload` 提供上次入库角度。重启后直接恢复续算，不依赖内存保存的上次数值。该角度处理不增加报文字段；发送状态由独立的 `report_*` 列记录。
- 按零点保持不变处理，不检测零点变更。已有零点但没有有效历史或换SN时，第一条扣零起算；不更改设备更新时间或快照入库时间。
- 每次从数据库读取前值，不维护额外内存状态；入库失败时保留原有采集重试机制。相同采集时间重试时，数据库中的原始值与当前值相同，增量为0，不会重复放大。历史不回写、不重算。
- 结果仍写入原有 `payload` 的X/Y位置及状态缓存 `angleX/Y`，角度最终保留6位小数；`raw_data`、`rawAngleX/Y` 保留原始值。温度、振动、水位和设备原始报警状态保持原有处理。定时上报直接使用入库值，不再次放大。
- 统一倍率直接配置在主配置文件 `application.yml` 的 `incline.fluctuation` 下，默认 `enabled=true`、`factor=2`，不再配置各设备固定中心。所有INC设备使用同一倍率，包括新增设备。关闭放大或设为1时直接扣零入库，配置修改需重启。
- 统一增量放大会同时放大真实变化与噪声，不能作为灵敏度标定或设备健康证明。原数据统计和按窗口首条起算的离线算例见 [评估报告](document/incline-fluctuation-assessment/assessment.md)。复算命令：`python3 scripts/analyze_incline_fluctuation.py <ZIP路径> --output <报告目录> --config <配置片段输出路径>`；生成配置片段只包含开关和统一倍率，按需合并到主配置，不要用片段覆盖整个 `application.yml`。

振动孤立尖峰过滤：

- `vibration.filter` 默认作用于 `ZYXH-VIB-P01-002-02`、`CBXH-VIB-P01-001-03`，保留现有 Z 轴通道和 mG → m/s² 换算。
- 只过滤相邻三条采集记录中的单条孤立尖峰。突增判据满足以下任一分支：绝对幅值比邻点至少增大 `spike-min-delta`（默认 2 m/s²）；或绝对幅值达到历史基线的 `spike-ratio`（默认 10）倍，同时比邻点至少增大 `relative-min-delta`（默认 0.05 m/s²）。确认时，中间点对前后邻点均须满足突增判据；后一条必须恢复，且前后点的有符号差值不超过 `return-tolerance`（本项目 YAML 建议配置 0.05 m/s²，未配置时类默认值为 0.5 m/s²）。恢复容差过小会使孤立尖峰因未恢复而被保留；它不是振动幅值上限。2 是幅值增量，不是绝对值上限或 ±2g 量程。
- 历史基线取最近 `baseline-window-size`（默认 24）条正常记录的绝对幅值中位数；不足时使用已有记录，首条直接放行。倍数计算使用 `noise-floor`（默认 0.001 m/s²）作为分母下限，防止基线接近零时放大倍数。待确认点、连续高值、报警/故障/状态未知记录不进入基线。
- 正常点立即入库，等待定时任务统一上报；疑似尖峰等下一条确认。若第二条相对突增前邻点和冻结的历史基线仍满足突增判据，两条立即原值放行；本轮后续高值持续放行，直到恢复基线，期间不再暂存或过滤单点。恢复后才重新识别下一轮孤立尖峰。未恢复、任一点报警/故障/状态未知时保留。空值和非有限数直接跳过，并打断相邻关系；无效数据、状态异常、采集间隔过长或待确认超时后重新建立历史窗口。
- 相邻采集间隔上限及待确认超时为 `max-gap-seconds`（默认 5400 秒，适配当前约每小时一条的上报周期）。缺少邻点、间隔过长、等待超时时无法确认孤立性，按原值放行；超时任务每分钟检查一次。
- 延后放行保留原始采集时间，定时上报仍按此时间判断有效期，确认丢弃的点记录告警及持久化过滤标记，避免回查时重新入库。入库失败回滚窗口状态，保留重试机会。窗口保存在内存中，进程重启后重新建立。
- 接口文档把 `accMaxX/Y/Z` 定义为各轴在采样周期内的最大变化量，把 `accX/Y/Z` 定义为重力加速度分量；后者不替代振动峰值。文档未明确这些字段的单位，当前沿用已有 mG 换算，仍需设备方确认。
- 该规则只做周期统计值的去尖峰，不能证明峰值一定是假数据；真实短时冲击也可能只占一条记录。报警记录保留供核查，振荡分析仍需要更高频率的原始波形。
